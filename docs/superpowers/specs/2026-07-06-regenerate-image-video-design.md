# 重新生成图片与视频入口设计

## 背景

剧集分镜页已经具备生成分镜图片和视频的能力，但“重新生成”入口不够明确：首帧/尾帧缩略图点击后可以重新生成，但用户不容易发现；视频按钮已有视频时仍显示“生成视频”，无法明确表达会覆盖当前视频。

本设计在不新增后端接口的前提下，将现有能力显性化，让用户可以分别重新生成图片和视频。

## 目标

- 在分镜页为首帧、尾帧图片提供明确的重新生成入口。
- 在分镜页为已有视频提供明确的“重新生成视频”入口。
- 点击后复用现有生成流程，并覆盖对应分镜资源字段。
- 重新生成失败时保留旧资源。

## 非目标

- 不做“一键同时重新生成图片和视频”。
- 不做批量重新生成。
- 不新增后端 API。
- 不删除旧静态文件。
- 不改变现有图片、视频生成参数逻辑。
- 不自动重新合成成片视频。

## 涉及页面

主要修改：

- `frontend/app/pages/drama/[id]/episode/[episodeNumber].vue`

后端接口和服务保持不变。

## 现有能力复用

### 图片生成

现有首帧/尾帧图片生成函数：

- `genShotFrame(sb, 'first_frame')`
- `genShotFrame(sb, 'last_frame')`

现有后端接口：

- `POST /api/v1/images`

生成完成后后端会覆盖写入：

- `storyboards.firstFrameImage`
- `storyboards.lastFrameImage`

### 视频生成

现有视频生成函数：

- `genVid(sb)`

现有后端接口：

- `POST /api/v1/videos`

生成完成后后端会覆盖写入：

- `storyboards.videoUrl`

## 用户交互设计

### 首帧/尾帧图片

每个分镜的首帧、尾帧区域根据资源状态显示不同文案：

- 没有图片时：显示“生成首帧”或“生成尾帧”。
- 已有图片时：显示“重新生成”入口。
- 正在生成时：显示现有 pending 状态，并禁用重复点击。

点击“重新生成”时，调用现有 `genShotFrame`。新图片生成成功后刷新分镜数据并替换展示；失败时保留旧图片。

### 视频

视频按钮根据资源状态显示不同文案：

- 没有视频时：显示“生成视频”。
- 已有视频时：显示“重新生成视频”。
- 正在生成时：显示“生成中”。

点击“重新生成视频”时，调用现有 `genVid(sb)`。新视频生成成功后覆盖展示；失败时保留旧视频，并沿用现有失败提示。

## 状态与错误处理

沿用现有前端状态：

- `pendingShotFrameKeys`：控制首帧/尾帧生成中的禁用与 loading 状态。
- `pendingVideoIds`：控制视频生成中的禁用与 loading 状态。
- `failedVideoMessages`：展示视频生成失败信息。

错误处理规则：

- 图片重新生成失败：结束 pending 状态，旧图片继续保留。
- 视频重新生成失败：结束 pending 状态，旧视频继续保留，显示失败信息。
- 生成过程中禁用对应入口，避免重复提交。

## 实现范围

预计只需要修改前端页面：

1. 调整首帧/尾帧图片区域，使已有图片时的重新生成入口更明确。
2. 调整视频按钮文案：已有视频时显示“重新生成视频”。
3. 必要时补充少量 CSS，使入口在已有图片场景下可见且不遮挡预览。

不需要修改：

- `frontend/app/composables/useApi.ts`
- 后端 routes
- 后端 services
- 数据库 schema

## 验收标准

- 分镜没有首帧/尾帧图片时，仍可生成图片。
- 分镜已有首帧/尾帧图片时，可以看到明确的“重新生成”入口。
- 点击重新生成首帧/尾帧后，会重新触发图片生成，并在成功后替换旧图。
- 分镜没有视频时，按钮显示“生成视频”。
- 分镜已有视频时，按钮显示“重新生成视频”。
- 点击重新生成视频后，会重新触发视频生成，并在成功后替换旧视频。
- 生成失败时不会清空旧图片或旧视频。
- TypeScript/Vite 构建不引入新的模板或类型错误。
